## Опис реалізованого функціоналу

У межах даної практичної роботи мовою **C** було реалізовано власний алокатор динамічної пам'яті, який забезпечує повноцінне керування пам'яттю у просторі користувача.

### 1. Організація метаданих та вирівнювання пам'яті
* **Вирівнювання блоків:** Усі розміри виділених блоків та структура метаданих `struct block_meta` вирівнюються до межі **8 байтів** (`ALIGNMENT = 8`) для коректної роботи на 64-бітній архітектурі. Розмір заголовка метаданих `META_SIZE` становить 32 байти.
* **Двозв'язний список:** Керування виділеними та вільними ділянками пам'яті здійснюється за допомогою глобального двозв'язного списку (`head` та `tail`), де кожен елемент зберігає розмір блоку (`size`), статус (`STATUS_FREE`, `STATUS_ALLOC`, `STATUS_MAPPED`) і посилання на сусідні блоки (`prev`, `next`).

```c
#define ALIGNMENT 8
#define ALIGN(size) (((size) + (ALIGNMENT - 1)) & ~(ALIGNMENT - 1))
#define META_SIZE (ALIGN(sizeof(struct block_meta)))
#define MMAP_THRESHOLD (128 * 1024)

struct block_meta *head = NULL;
struct block_meta *tail = NULL;
int heap_preallocated = 0;
```

---

### 2. Основні функції алокатора

* **`os_malloc(size_t size)`**  
  Виділяє блок пам'яті розміром `size` байтів. Якщо вирівняний розмір разом із метаданими перевищує або дорівнює порогу `MMAP_THRESHOLD` (128 КБ), пам'ять запитується безпосередньо через системний виклик `mmap()`. Для менших запитів виконується пошук оптимального вільного блоку на купі (`find_best_fit`), а за його відсутності — розширення купи через `sbrk()`.

* **`os_calloc(size_t nmemb, size_t size)`**  
  Виділяє пам'ять для масиву з `nmemb` елементів розміром `size` байтів кожен та заповнює виділену область нулями за допомогою `memset()`. Порогом для використання `mmap()` тут виступає розмір сторінки пам'яті (`getpagesize()`, 4 КБ).

* **`os_free(void *ptr)`**  
  Звільняє раніше виділений блок пам'яті. Блоки зі статусом `STATUS_MAPPED` повертаються операційній системі за допомогою `munmap()`, а блоки на купі отримують статус `STATUS_FREE` для подальшого повторного використання.

* **`os_realloc(void *ptr, size_t size)`**  
  Змінює розмір виділеного блоку пам'яті. Обробляє граничні випадки (`ptr == NULL` працює як `os_malloc`, `size == 0` викликає `os_free`). При зменшенні виконує розбиття блоку на місці (`split_block`). При збільшенні намагається розширити блок шляхом поглинання наступних вільних блоків (`STATUS_FREE`) або дорозширення останнього блоку (`tail`) через `sbrk()`; якщо це неможливо - виділяє новий блок, копіює дані через `memcpy()` та звільняє старий.

## Механізми оптимізації та мінімізації фрагментації

1. **Попереднє виділення купи (Heap Preallocation):** Під час першого запиту до купи виділяється великий блок розміром 128 КБ (`MMAP_THRESHOLD`) через `sbrk()`, що суттєво зменшує кількість системних викликів при малих алокаціях.
2. **Пошук найкращого блоку (Best-fit, `find_best_fit`):** Серед усіх вільних блоків обирається блок зі статусом `STATUS_FREE`, який має мінімальний достатній розмір (`curr->size >= aligned_size`).
3. **Розбиття блоків (Block Splitting, `split_block`):** Якщо вибраний блок більший за запитуваний щонайменше на `META_SIZE + 8` байтів, він ділиться на зайнятий блок потрібного розміру та новий вільний блок.
4. **Злиття вільних блоків (Coalescing, `coalesce_all_free_blocks`):** Перед пошуком суміжні блоки зі статусом `STATUS_FREE` об'єднуються в один великий блок для запобігання зовнішній фрагментації.
5. **Розширення останнього блоку (Expand last block):** Якщо на купі немає вільного блоку достатнього розміру, але останній блок (`tail`) вільний, виконується довиділення лише відсутньої різниці байтів через `sbrk()`.

## Висновок
В ході виконання роботи, мовою C було реалізовано власний алокатор динамічної пам'яті (бібліотеку libosmem.so), який забезпечує повноцінне 
керування пам'яттю у просторі користувача через функції os_malloc, os_calloc, os_realloc та os_free. Залежно від обсягу запитуваної пам'яті алокатор динамічно 
обирає оптимальний системний механізм: для малих і середніх блоків використовується керування купою за допомогою системного виклику sbrk(), а 
для великих блоків (від 128 КБ для os_malloc/os_realloc та від розміру сторінки 4 КБ для os_calloc) застосовується пряме відображення пам'яті через mmap() із 
подальшим звільненням через munmap(). У процесі розробки було реалізовано та протестовано повний комплекс механізмів оптимізації роботи з купою та мінімізації фрагментації пам'яті на 
базі двозв'язного списку метаданих (struct block_meta) з вирівнюванням блоків до 8 байтів. Зокрема, впроваджено попереднє виділення купи (preallocation) 
розміром 128 КБ при першому зверненні, пошук оптимального вільного блоку за стратегією best-fit, розбиття великих вільних блоків (splitting) при наявності 
достатнього залишку, автоматичне злиття суміжних вільних блоків (coalescing), а також розширення останнього блоку купи на місці без зайвого копіювання 
даних. Розроблений алокатор пам'яті успішно проходить тестування без витоків пам'яті, що підтверджує виконання усіх 40 автоматизованих функціональних тестів.
